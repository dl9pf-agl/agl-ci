# 04 Signing, attestation, verification

Status: **untested** (first publish pending). Release-engineer signature: see chapter 06.

## What is produced per image digest
1. **CI signature**: `cosign sign` keyless. Certificate identity
   `https://github.com/<repo>/.github/workflows/images.yml@<ref>`, issuer `https://token.actions.githubusercontent.com`,
   logged in Rekor.
2. **SBOM attestation**: SPDX JSON generated by syft (anchore/sbom-action) from the exact OCI archive,
   attached with `cosign attest --type spdxjson`.
3. **SLSA build provenance**: `actions/attest-build-provenance` (GitHub attestations, pushed to the registry).
4. **Release countersignature** (tags only, local): YubiKey key, `cosign sign --sk`.

## Why the identity must be pinned
`cosign verify` without `--certificate-identity` accepts any valid Sigstore signature. All scripts and the
workflow's `verify` job pin workflow path and ref. `verify-release.sh` accepts only `refs/heads/main` and
`refs/tags/v*`.

## Consumer verification
```
scripts/verify-release.sh ghcr.io/dl9pf-agl/agl-ci/builder:1.0.0 --release
```
Use the printed `@sha256:` digest in workflows (`container: image: ...@sha256:...`), never a tag.

## Known limits
- Provenance from `attest-build-provenance` is SLSA Build L2 (GitHub-hosted builder, signed). L3 needs the
  isolated SLSA generator reusable workflow; evaluate later (see chapter 02, 07).
- Key-based release signatures are checked against `keys/release/*.pub` of the checkout in use; trust in that
  checkout is a trust root (signed commits, branch protection).
