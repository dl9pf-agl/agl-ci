# 04 Signing, attestation, verification

*Read this if you verify an image, or check how images and releases are signed.*

Status: scripts tested locally with a stubbed cosign and real syft (SBOM 345 packages); keyless signing is **in use**: the publish job signs, a fresh runner verifies, and `kit/deploy.sh` runs `cosign verify` on both hosts before using an image. Release-engineer signature: see chapter 06.

## What is produced per image digest
1. **CI signature**: `cosign sign` keyless. Certificate identity
   `https://github.com/<repo>/.github/workflows/images.yml@<ref>`, issuer `https://token.actions.githubusercontent.com`,
   logged in Rekor.
2. **SBOM attestation**: SPDX JSON generated by a sha256-pinned `syft` from the exact OCI archive,
   attached with `cosign attest --type spdxjson`.
3. **SLSA build provenance**: predicate generated by `scripts/sign-image.sh` (builder id, source commit, run URL,
   all pins) and attached with `cosign attest --type slsaprovenance1`. The forge adapter supplies the values via
   env (`BUILDER_ID`, `SOURCE_URI`, `SOURCE_COMMIT`, `RUN_URL`), so the script is forge-independent.
4. **Release countersignature** (tags only, local): YubiKey key, `cosign sign --sk`.

## Why the identity must be pinned
`cosign verify` without `--certificate-identity` accepts any valid Sigstore signature. All scripts and the
workflow's `verify` job pin workflow path and ref. `verify-release.sh` accepts only `refs/heads/main` and
`refs/tags/v*`.

## Consumer verification
```
scripts/verify-release.sh ghcr.io/dl9pf-agl/agl-ci/builder:1.0.0 --release
```
Use the printed `@sha256:` digest in workflows (`container: image: ...@sha256:...`), never a tag.

## Known limits
- Provenance is generated by the same job that builds/pushes and signed with the workflow identity: SLSA Build L2
  evidence (hosted builder, signed). L3 needs the isolated SLSA generator reusable workflow; evaluate later.
- Optional GitHub extra (not in the verify policy, not built): add `actions/attest-build-provenance` per image with
  `push-to-registry: true` and `attestations: write`; verify with `gh attestation verify`.
- Key-based release signatures are checked against `keys/release/*.pub` of the checkout in use; trust in that
  checkout is a trust root (signed commits, branch protection).
